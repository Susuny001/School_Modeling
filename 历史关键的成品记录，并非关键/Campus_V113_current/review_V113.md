# V113 严格双项复核记录

> 说明：当前环境没有可调用的外部真人“专家”审查工具，因此这里不冒充外部专家，也不伪造“专家已通过”。下面是按用户指定的两套准则做的严格复核记录。

## 复核 A：外观 / 建模真实性（对应“专家1”准则）

**结论：FAIL，不通过。**

判定标准采用用户给出的最高标准：把六个给定坐标/角度下的模型截图与真实图并排比较，要求“看不出来哪个是真实图片”，并且禁止贴图、禁止把视频/图片像素投射到模型上。

### 已核实完成的硬性项
- GLB 的 `textures / images / samplers / TEXCOORD / COLOR` 均为 0；禁止贴图这一项通过结构检查。
- 旗杆红旗是双面三角形实体网格，不是图片平面；旗杆材质 `metallicFactor >= 0.9`、`roughnessFactor <= 0.2`，查看器实际读取这两个参数并计算镜面高光。
- 旗杆前灰楼已取消弧形和浅折线方案，V113 使用一整条笔直主楼体；中央入口、玻璃山墙、柱廊、楼梯玻璃塔、正反立面窗格均为几何体。
- 科学楼中央车行门洞使用左右楼翼 + 上部桥体的分体几何，门洞本身是真正空的；球顶、玻璃山墙、楼梯塔、柱廊均为几何。
- 对照 5/6 增加了停车场、车辆、树列、主入口轴线和校门；对照 4 增加红色竖幅与金色立体笔画；航拍增加远景城市体块和山脊。

### 拒绝理由 / 为什么仍然不能通过
- `V113_compare_board.jpg` 中六组对照仍可直接分辨真实图和模型图，达不到“无法分辨哪个是真的”的标准。
- 树木冠层仍明显是低多边形几何，叶片密度、枝干层级、透光和随机轮廓与真实环境差距大。
- 建筑立面虽已纠正主要形状，但窗型、墙板接缝、空调、入口尺度、雨棚、屋顶设备等仍未达到逐处照片级一致。
- 对照 3/4 的全局建筑布局、道路/花园/树群密度及远景城市关系仍有明显偏差。
- 对照 5/6 的科学楼比例和前场关系明显改善，但停车车辆、校门、背景建筑、山体轮廓仍是建模感强的几何简化。
- 当前离线查看器是无贴图的实时 WebGL 几何渲染，光照、天空、玻璃、植被和表面微细节仍明显区别于真实摄影。

因此，按用户规定，“专家1”对应准则必须判定 **不通过**，不能为了交付而写成通过。

## 复核 B：打开流程 / 移动人性化（对应“专家2”准则）

**结论：PASS（基于静态代码与文件结构核验；没有冒充真人浏览器实测）。**

通过依据：
- `打开地图_V113.html` 为单文件自包含入口，模型已内嵌，不需要网络、服务器或 three.js。
- 点击画面任意位置即可进入 Pointer Lock 鼠标视角；Alt 主动释放，ESC 保留浏览器标准 Pointer Lock 退出行为。
- 释放鼠标后视角不会重置，WASD / Space / Shift 的移动更新也没有被 Pointer Lock 状态门控，所以仍能移动并可直接点击“设置”。
- 设置内可调灵敏度、移动速度、FOV、六个移动键位；可传送到 `(x,y,z)` 且不修改当前 yaw/pitch。
- 增加六个“对照视角”一键按钮，直接使用用户给出的六组坐标与水平角/俯仰角，便于核对。
- HUD 坐标和角度均显示到 0.1。

限制：当前沙箱没有一个可让真人实际点击本地 `file://` 页面并体验 Pointer Lock 的交互浏览器会话，因此这里把“代码/结构通过”与“真人外部专家实测”明确区分。

## 总结

- 复核 A：**FAIL**
- 复核 B：**PASS（静态/结构）**
- 总体：**FAIL**。按用户的“双专家任一不通过就打回”规则，V113 不能宣称最终验收通过。
