## 【每轮生成内容】（不是交付）

每轮稳定工作版本实际生成并核对：

1. 同版统一 `.glb`；
2. 同版可编辑原生 `.blend`；
3. 同版实际 `.fbx`，精确到最小的子类部件（如窗户、门、某面墙等），具体来说是用户在unity上微调建模，就是子类的程度不要仅细分到一类物品，如north_windows，而它下面还有每一个window都应该可以单独调整，这样才方便用户微调，不能一动就会动一类的。包括但不限于栅栏、窗户（每种）、门（每种）、树、墙、material、...等等。导入unity后，应该既能移动父类物体（如楼房），又能单独操作挂在父类上的物体（如教学楼三楼第二个窗户）;
4. 同版可导入unity的所有最小预制件的`.unitypackage`文件，这个是在3上衍生出来的，“除了fbx，并且要是能给用户直接做成一个fbx_prefab包就最好了”。;
5. 同版统一 HTML 入口，嵌入的模型与本版 GLB 相同；
6. 由该版实际模型渲染的演示图，包含能检视本次改动的角度。同位置视频图和建模图对照图。
(注意：如果是在**github协作**中，就是最后文件要push进github的，3、4不需要生成，因为这俩文件太大了。github协作只需commit本版本包，里面有1，2，5，6，然后还得更新其他文件)

按**流程：给AI**要求提交、保存日志、检查并删除旧版文件，也不能只有局部样件而称统一模型已输出。构造失败的内部试验，必须明确拒绝，不得算为一个版本，需要这版确认完成后才允许commit。

生成的fbx必须满足**可编辑性**：

- 窗户、各类门、栏段、树、墙、桌、椅、书、书箱等实际单件应能单独选择与调整。
- 原生和 FBX 保留建筑、楼层、教室等合理层级与轴心。
- 玻璃、窗框、墙洞和内部空间是真实几何和材质，不靠照片伪装。
- 用户希望能直接用的 FBX Prefab 包；如实际生成 `.unitypackage`，须是本版模型、实际导入并检查，不能拿历史包冒新包。
